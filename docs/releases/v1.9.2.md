# dietcode-plugin v1.9.2 — Kernel Bridge Performance Pass

**Release date:** 2026-06-09

## One-line summary

Adds bridge readiness caching, workspace-open reuse, progress write batching, mutation
locking, and phase-level performance telemetry for faster coherent patch workflows
without weakening safety gates.

## What shipped

Conservative latency reductions — no safety gate changes.

| Optimization | Config key | Default |
| --- | --- | --- |
| Preflight readiness cache | `preflight_cache_ttl_ms` | 5000 |
| Workspace open reuse | `workspace_open_cache` | true |
| Progress JSONL batching | `progress_flush_interval_ms` | 250 |
| Optional verify timeout | `verify_timeout_ms` | 0 (use `request_timeout_sec`) |
| Per-workspace mutation lock | `max_concurrent_mutations_per_workspace` | 1 |

Also: patch fast path when `taskId` present and no workspace drift (`apply_patch_with_coherence`
instead of full recovery loop), verify heartbeat during long runs, journal dedup TTL index.

### Operator surface

```text
/dietcode kernel perf --last 10
python scripts/kernel_bridge_perf.py --compact
```

Progress events include `phase_duration_ms` and `perf_bucket` for:
`socket/preflight`, `workspace.open`, `coherence.read`, `anchor.refresh`,
`patch.validate`, `patch.apply`, `verify.run`, `journal.recording`,
`convergence.checking`.

### Reading perf output

| Dominant bucket | Next action |
| --- | --- |
| `anchor.refresh` / coherence recover | Anchor freshness tuning (Phase 8 candidate) |
| `verify.run` | Leave alone unless cheap/expensive verify tiers |
| `journal.recording` | JoyZoning write path optimization |
| `workspace.open` (high count + high ms) | Check `workspace_open_cache` / cache invalidation |
| `socket/preflight` | Socket/token health — `make -C kernel restart-agent-server-fast` |

Look for `cached: true` on progress events to confirm readiness/workspace cache hits.
Look for `fast_path: true` on `patch.apply` to confirm drift-free coherence fast path.
