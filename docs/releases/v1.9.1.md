# dietcode-plugin v1.9.1 — Kernel Observability Polish

**Release date:** 2026-06-09

## One-line summary

Adds structured kernel progress telemetry, timeline views, gate explanations, and
operator recovery hints for long-running coherent patch and verify operations.

## What shipped

Observability only — no new mutation authority, no safety fuse changes.

```text
Phase 6   progress telemetry + slash commands + agent hints
Phase 6B  human summaries, timeline, multi-op views, stress tests
```

The kernel bridge now distinguishes operator states that feel different in practice:

```text
slow | stalled | waiting | failed | blocked | unsafe | recovering | done
```

### Operator surface

| Command | Purpose |
| --- | --- |
| `/dietcode kernel progress` | Human summary of current operation |
| `/dietcode kernel progress --timeline` | Phase timeline with durations |
| `/dietcode kernel progress --last 5` | Recent operations summary |
| `/dietcode kernel progress --operation <id>` | Filter tail/timeline by operation |
| `/dietcode kernel last-error` | Normalized error envelope + recovery hints |
| `/dietcode kernel explain-gate` | Closed gates, fixes, raw-write behavior |

Progress logs: `~/.dietcode/session/kernel-progress.jsonl` and
`kernel-progress-current.json`.

### Agent ergonomics

`dietcode_kernel` responses include `_kernel_operator_hints` and
`_kernel_error_envelope` with `next_action`, `safe_to_retry`, `retry_command`,
`diagnostic_command`, and `rollback_command` when relevant.

## Upgrade notes

- Patch release on top of v1.9.0 — no config migration required.
- No breaking changes to BroccoliDB, JoyZoning, JSDP, or kernel mutation behavior.
- Linux installs unchanged (graceful degradation; progress commands work, logs empty until used).
